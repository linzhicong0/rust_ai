Overview

The Rust AI Framework is a modular, async-first toolkit for building LLM-powered applications. It provides a trait-based abstraction over multiple providers, built-in streaming, structured output, tool calling, and autonomous agents — all with Rust's safety and performance guarantees.

🔄

Agents
Autonomous ReAct loops
🎯
Structured Output
JSON schema + validation

02

Quick Start

Step 1 — Add Dependencies

Add the core crate and your chosen provider to Cargo.toml.

Cargo.toml
[dependencies]
ai-core = { path = "crates/ai-core" }
ai-provider-openai = { path = "crates/ai-provider-openai" }
tokio = { version = "1", features = ["full"] }

Step 2 — Set Environment Variables

The framework reads API keys from environment variables.

export OPENAI_API_KEY="sk-..."
export ANTHROPIC_API_KEY="sk-ant-..."
export GOOGLE_API_KEY="AIza..."

Step 3 — Your First Completion

Create a client, send a message, and print the response.

src/main.rs
use ai_core::client::Client;
use ai_core::types::{Message, ModelConfig};
use ai_provider_openai::OpenAiProvider;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Create a provider with your API key
    let provider = OpenAiProvider::new(std::env::var("OPENAI_API_KEY")?);

    // Wrap it in a client
    let client = Client::new(provider)
        .with_config(ModelConfig::new("gpt-4"));

    // Send a message
    let response = client
        .complete(vec![Message::user("What is Rust?")])
        .await?;

    println!("{}", response.content);
    Ok(())
}
💡
Tip: Swap OpenAiProvider for any other provider (Anthropic, Google, Ollama, DeepSeek) without changing any other code. The Provider trait ensures a uniform interface.

The Provider Trait

All providers implement this async trait with four core methods.

#[async_trait]
pub trait Provider: Send + Sync {
    async fn complete(
        &self,
        messages: Vec<Message>,
        config: &ModelConfig,
        tools: &[ToolDescriptor],
    ) -> Result<CompletionResponse, ProviderError>;

    fn stream(
        &self,
        messages: Vec<Message>,
        config: &ModelConfig,
        tools: &[ToolDescriptor],
    ) -> BoxStream<'static, Result<StreamChunk, ProviderError>>;

    async fn embed(&self, texts: Vec<String>) -> Result<Vec<Vec<f32>>, ProviderError>;
    fn name(&self) -> &str;
}
04

Chat Completions

Creating Messages

Use the Message builder methods to construct conversations.

use ai_core::types::Message;

let messages = vec![
    Message::system("You are a helpful assistant."),
    Message::user("Explain ownership in Rust."),
];

Configuring the Model

Use ModelConfig to set the model and generation parameters. Convenience constructors are available for popular models.

use ai_core::types::ModelConfig;

// From scratch
let config = ModelConfig::new("gpt-4")
    .temperature(0.7)
    .max_tokens(1024)
    .top_p(0.9);

// Convenience constructors
let config = ModelConfig::gpt4();
let config = ModelConfig::claude_opus();

Basic Completion

Send messages and receive a complete response.

let client = Client::new(provider)
    .with_config(ModelConfig::new("gpt-4"));

let response = client
    .complete(vec![
        Message::system("You are a Rust expert."),
        Message::user("Explain lifetimes."),
    ])
    .await?;

println!("Content: {}", response.content);
println!("Tokens used: {}", response.usage.total_tokens);
println!("Finish reason: {:?}", response.finish_reason);

Multi-Turn Conversation

Build a conversation by including prior assistant messages.

let messages = vec![
    Message::user("What is Rust?"),
    Message::assistant("Rust is a systems programming language..."),
    Message::user("What are its advantages?"),
];

let response = client.complete(messages).await?;

Embeddings

Generate vector embeddings for text.

let embeddings = client
    .embed(vec![
        "Rust is fast".to_string(),
        "Python is easy".to_string(),
    ])
    .await?;

for (i, emb) in embeddings.iter().enumerate() {
    println!("Embedding {}: {} dimensions", i, emb.len());
}

Streaming

Stream tokens in real time. The stream() method returns a BoxStream that yields StreamChunk items as they arrive from the provider.

Basic Streaming

use futures::StreamExt;

let mut stream = client.stream(vec![
    Message::user("Write a haiku about Rust."),
]);

while let Some(result) = stream.next().await {
    match result {
        Ok(chunk) => {
            if let Some(delta) = chunk.delta {
                print!("{}", delta);
            }
            if let Some(reason) = chunk.finish_reason {
                println!("\nFinished: {:?}", reason);
            }
        }
        Err(e) => eprintln!("Error: {}", e),
    }
}
ℹ️
Note: Streaming returns BoxStream<'static, Result<StreamChunk, ProviderError>>. Use futures::StreamExt to iterate. Each StreamChunk contains an optional delta (text) and optional finish_reason.

Tool Calling

Define tools with the Tool trait, register them, and let the LLM decide when to call them. The framework handles the full tool-calling lifecycle.

Defining a Tool

Implement the Tool trait with a descriptor and an async execute method.

use ai_core::tool::{Tool, ToolDescriptor, ToolOutput, ToolError};
use serde_json::json;
use async_trait::async_trait;

struct WeatherTool;

#[async_trait]
impl Tool for WeatherTool {
    fn descriptor(&self) -> ToolDescriptor {
        ToolDescriptor::new(
            "get_weather",
            "Get the current weather for a location",
            json!({
                "type": "object",
                "properties": {
                    "location": { "type": "string" },
                    "unit":    { "type": "string", "enum": ["celsius", "fahrenheit"] }
                },
                "required": ["location"]
            }),
        )
    }

    async fn execute(&self, input: serde_json::Value) -> Result<ToolOutput, ToolError> {
        let location = input["location"].as_str().unwrap_or("unknown");
        // Your API call here...
        Ok(ToolOutput::success(format!("72°F in {}", location)))
    }
}

Using Tools with a Client

Pass tool descriptors to complete_with_tools. The model will return tool calls in the response.

let weather = WeatherTool;
let descriptors = vec![weather.descriptor()];

let response = client
    .complete_with_tools(
        vec![Message::user("What's the weather in Tokyo?")],
        &descriptors,
    )
    .await?;

for tool_call in &response.tool_calls {
    println!("Model wants to call: {}", tool_call.name);
    println!("Arguments: {}", tool_call.arguments);

    // Execute the tool and continue the conversation
    let result = weather.execute(tool_call.arguments.clone()).await?;
}

Tool Registry

Register multiple tools and look them up by name.

use ai_core::tool::ToolRegistry;

let mut registry = ToolRegistry::new();
registry.register(WeatherTool);
registry.register(SearchTool);
registry.register(CalculatorTool);

// Get all descriptors for sending to the model
let descriptors = registry.descriptors();

// Look up and execute a tool by name
if let Some(tool) = registry.get("get_weather") {
    let result = tool.execute(json!({"location": "Paris"})).await?;
}

Tool Macro Ergonomic

Use the #[tool] procedural macro to define tools from simple async functions.

use ai_tools_macros::tool;
use ai_core::tool::{ToolOutput, ToolError};

#[tool(name = "greet", description = "Greet a user by name")]
async fn greet_user(input: serde_json::Value) -> Result<ToolOutput, ToolError> {
    let name = input["name"].as_str().unwrap_or("world");
    Ok(ToolOutput::success(format!("Hello, {}!", name)))
}

Tool Outputs

MethodDescription
ToolOutput::success(text)Successful text result
ToolOutput::error(text)Error result (model sees the error)
ToolOutput::json(&value)Serialize a struct as JSON output

Structured Output

Enforce JSON schema on model responses. The framework validates output and retries automatically when validation fails.

JSON Schema Validation

Define a JSON schema and use the structured output validator with automatic retries.

use ai_core::structured::{StructuredOutputConfig, StructuredOutputValidator, complete_structured};
use serde_json::json;

let schema = json!({
    "type": "object",
    "properties": {
        "name":  { "type": "string" },
        "age":   { "type": "integer" },
        "email": { "type": "string", "format": "email" }
    },
    "required": ["name", "age"]
});

let config = StructuredOutputConfig::new(schema)
    .with_max_retries(3);

let validator = StructuredOutputValidator::new(config)?;

let result = complete_structured(&validator, |prompt| {
    Box::pin(async move {
        // Call your provider here with the augmented prompt
        let response = client.complete(vec![
            Message::user(prompt)
        ]).await?;
        Ok(response.content)
    })
}).await?;

assert_eq!(result["name"], "Alice");
assert_eq!(result["age"], 30);

Extracting JSON from Responses

The framework provides a helper to extract JSON from markdown code blocks or raw text.

use ai_core::structured::extract_json;

let raw = r#"Here is the data:
```json
{"name": "Alice", "age": 30}
```
"#;

let json_str = extract_json(raw);
assert_eq!(json_str, Some(r#"{"name": "Alice", "age": 30}".to_string()));

Agents

Build autonomous agents that reason, use tools, and iterate with a ReAct (Reason + Act) loop. Agents combine a provider, memory, tools, and a persona.

Building an Agent

Use the fluent AgentBuilder to configure an agent with a provider, memory, tools, and persona.

use ai_agent::{AgentBuilder, Agent};
use ai_memory::InMemoryMemory;
use ai_provider_openai::OpenAiProvider;

let memory = InMemoryMemory::new(100);
let provider = OpenAiProvider::new(std::env::var("OPENAI_API_KEY")?);

let agent = AgentBuilder::new(memory)
    .provider(provider)
    .role("Senior Rust Developer")
    .goal("Write correct, idiomatic Rust code")
    .backstory("You have 10 years of Rust experience.")
    .tool(WeatherTool)
    .tool(SearchTool)
    .max_iterations(10)
    .build()?;

Running an Agent

Call run() with a prompt. The agent will reason, call tools, and iterate until it produces a final answer.

let output = agent
    .run("What's the weather in Tokyo and what should I wear?")
    .await?;

println!("Agent response: {}", output.content);
println!("Iterations used: {:?}", output.iterations);

Streaming Agent Events

Watch the agent's reasoning steps and tool calls in real time.

let mut stream = agent.stream("Analyze this codebase");

while let Some(event) = stream.next().await {
    match event {
        Ok(AgentEvent::Thinking(text)) => {
            println!("[Thinking] {}", text);
        }
        Ok(AgentEvent::ToolCall { name, arguments }) => {
            println!("[Tool] {}({})", name, arguments);
        }
        Ok(AgentEvent::ToolResult(result)) => {
            println!("[Result] {}", result.content);
        }
        Ok(AgentEvent::Complete(output)) => {
            println!("[Done] {}", output.content);
        }
        Err(e) => eprintln!("Error: {}", e),
    }
}

Adding Tools Dynamically

Add tools after building with with_tool().

let agent = agent
    .with_tool(CalculatorTool)
    .with_tool(FileReadTool);
⚠️
Caution: Set max_iterations to prevent infinite loops. The agent will return AgentError::MaxIterationsExceeded if it hits the limit.

Memory

Memory backends store conversation history. All implement the Memory trait with add, get, search, and clear.

Available Backends

BackendUse CaseDescription
InMemoryMemorySingle sessionBounded FIFO buffer in memory
ThreadScopedMemoryMulti-sessionSeparate history per thread ID
SharedMemoryThread-safe sharedArc-wrapped memory for concurrent access

InMemoryMemory

The simplest backend. Stores up to N entries in a FIFO buffer.

use ai_memory::InMemoryMemory;

let memory = InMemoryMemory::new(50); // capacity = 50 entries

// Add entries
memory.add(MemoryEntry::user("Hello!")).await?;
memory.add(MemoryEntry::assistant("Hi! How can I help?")).await?;

// Retrieve all (or limit)
let history = memory.get(Some(10)).await?;

// Search (basic text matching)
let results = memory.search("hello", 5).await?;

ThreadScopedMemory

Maintain separate conversation histories per thread or session.

use ai_memory::ThreadScopedMemory;

let memory = ThreadScopedMemory::new(100);

// Add to a specific thread
memory.add_to_thread("session-1", MemoryEntry::user("Hello")).await?;
memory.add_to_thread("session-2", MemoryEntry::user("Hi")).await?;

// Get history for a specific thread
let history = memory.get_thread("session-1", None).await?;

The Memory Trait

#[async_trait]
pub trait Memory: Send + Sync {
    async fn add(&self, entry: MemoryEntry) -> Result<(), MemoryError>;
    async fn get(&self, limit: Option<usize>) -> Result<Vec<MemoryEntry>, MemoryError>;
    async fn search(&self, query: &str, limit: usize) -> Result<Vec<MemoryEntry>, MemoryError>;
    async fn clear(&self) -> Result<(), MemoryError>;
}

Templates

The built-in template engine (powered by Tera) lets you compose prompts with variable interpolation and built-in agent templates.

Using Templates

use ai_core::template::TemplateEngine;
use std::collections::HashMap;

let mut engine = TemplateEngine::new()?;

// Add a custom template
engine.add_template("greeting",
    "Hello {{ name }}! You are {{ role }}."
)?;

// Render with variables
let mut ctx = HashMap::new();
ctx.insert("name".to_string(), json!("Alice"));
ctx.insert("role".to_string(), json!("admin"));

let rendered = engine.render("greeting", &ctx)?;
// "Hello Alice! You are admin."

Built-in Agent Templates

The engine ships with ready-made system prompt templates for common agent personas.

Template NamePurpose
agent_defaultGeneral-purpose assistant
agent_coderCode generation and review
agent_researcherResearch and analysis tasks
agent_writerContent creation
 
// Use a built-in template
let prompt = engine.render_builtin("agent_coder", &ctx)?;

Loading from a Directory

let mut engine = TemplateEngine::with_templates_dir("templates/")?;
// Loads all .tera / .txt files from the directory

Configuration

The framework supports layered configuration: defaults, config files, environment variables, and code overrides.

Loading Configuration

use ai_core::config::FrameworkConfig;

// Auto-load from file + environment
let config = FrameworkConfig::load()?;

// Load from a specific file
let config = FrameworkConfig::load_from_path("config.toml")?;

// Validate all settings
config.validate()?;

Programmatic Configuration

use ai_core::config::{FrameworkConfig, ProviderConfig};

let config = FrameworkConfig::default()
    .with_default_provider("openai")
    .with_default_model("gpt-4")
    .with_provider("openai", ProviderConfig {
        api_key_env: "OPENAI_API_KEY".to_string(),
        base_url: "https://api.openai.com/v1".to_string(),
        default_model: Some("gpt-4".to_string()),
    });

Error Handling

All errors are typed with thiserror and provide structured context for debugging.

Error Types

Error TypeSourceCommon Variants
ProviderErrorProvider operationsApi { status, body }, Auth, RateLimit, Timeout
AgentErrorAgent executionMaxIterationsExceeded, Provider(..), Tool(..)
ToolErrorTool executionExecution(msg), NotFound, InvalidInput
MemoryErrorMemory operationsFull, NotFound, Io(..)
StructuredOutputErrorStructured outputValidation(msg), MaxRetriesExceeded, JsonParse(..)

Handling Errors

use ai_core::error::ProviderError;

match client.complete(messages).await {
    Ok(response) => println!("{}", response.content),
    Err(ProviderError::Api { status, body }) => {
        eprintln!("API error {}: {}", status, body);
    }
    Err(ProviderError::RateLimit { retry_after }) => {
        eprintln!("Rate limited. Retry after {:?}s", retry_after);
    }
    Err(ProviderError::Timeout) => {
        eprintln!("Request timed out");
    }
    Err(e) => eprintln!("Unexpected error: {}", e),
}

Agent Error Handling

use ai_agent::AgentError;

match agent.run("Do something complex").await {
    Ok(output) => println!("{}", output.content),
    Err(AgentError::MaxIterationsExceeded) => {
        eprintln!("Agent could not complete in time");
    }
    Err(AgentError::Provider(e)) => {
        eprintln!("Provider error: {}", e);
    }
    Err(AgentError::Tool(e)) => {
        eprintln!("Tool error: {}", e);
    }
    Err(e) => eprintln!("Agent error: {}", e),
}
